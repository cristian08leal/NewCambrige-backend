Plataforma WebColegios Bot

Sistema Unificado de Automatizacion ETL con Playwright Chromium, Sincronizacion de Paz y Salvo e Importacion Inteligente de Datos Escolares

Playwright Chromium FastAPI Backend React 18 Dashboard PostgreSQL Sync

Descripcion General del Sistema

WebColegios Bot es una solucion integrada de administracion escolar de arquitectura mixta, diseñada para automatizar la extraccion, transformacion, sincronizacion y gestion de informacion de estudiantes y docentes de la plataforma de gestion academica WebColegios.

El sistema resuelve de manera eficiente la falta de sincronizacion automatica entre la plataforma oficial externa y la base de datos local utilizada para procesos administrativos de paz y salvo, reportes y control de matriculas.

Para lograr esto, el proyecto se compone de tres pilares fundamentales:

  1. Motor de Scraping y Automatizacion (ETL) basado en Playwright Chromium, encargado de extraer datos oficiales en formato PDF o HTML de la plataforma, procesarlos e importarlos aplicando parsing estructural y bypass dinamico de seguridad.
  2. Backend FastAPI que sirve como API REST y servidor web, gestionando la conexion a PostgreSQL, la logica de negocio, las transacciones robustas y la ejecucion asincrona del bot en hilos de ejecucion secundarios.
  3. Dashboard Web React (Vite) moderno que actua como interfaz de usuario para iniciar extracciones, previsualizar logs en tiempo real, visualizar tablas de datos, realizar importaciones manuales con control de duplicados en tiempo real y procesar archivos masivos mediante procesamiento en cliente.

Componentes Arquitectonicos

  • Frontend (React 18 + Vite): Proporciona una interfaz de usuario basada en variables CSS con una paleta cromatica corporativa (tonos vinotinto, beige y gris antracita).
    • Procesamiento en el Cliente (Client-side Parsing): Las importaciones masivas de archivos (CSV, XLSX, XLS, JSON) se analizan localmente usando la biblioteca SheetJS para evitar la sobrecarga del servidor con archivos pesados.
    • Mapeo Flexible: Asocia columnas del usuario con nombres arbitrarios a las columnas de la base de datos local usando un diccionario de sinonimos.
    • Validacion Previa: Valida datos fila por fila antes de enviar cualquier peticion al servidor, garantizando la integridad referencial y de tipos de datos.
  • Backend (FastAPI + Uvicorn): El backend en Python provee endpoints de alto rendimiento para interactuar con la base de datos y controlar el bot de automatizacion.
    • Concurrencia: Inicia las tareas pesadas de scraping en hilos de ejecucion secundarios (threads) para evitar congelar el servidor web principal y mantener el panel web responsivo.
    • Servidor de Estaticos: Ademas de la API REST, sirve la aplicacion compilada de React y archivos temporales de plantillas Excel.
  • Motor de Automatizacion (Playwright Chromium Engine): Implementa un patron de diseño modular para interactuar de manera fluida y robusta con el portal de WebColegios:
    • Playwright Chromium: Controla un navegador Chromium en modo visible (para desarrollo) o en modo headless (para produccion sin interfaz grafica).
    • Bypass de Captcha: Extrae y analiza la operacion aritmetica mostrada en pantalla mediante expresiones regulares, resolviendola e ingresandola dinamicamente antes de enviar el formulario.
    • Cierre de Ventanas Emergentes: Detecta y cierra de forma automatica modales como el panel de bienvenida institucional para acceder de inmediato al dashboard administrativo.
  • Base de Datos (PostgreSQL): Almacena la informacion en tres tablas principales con indices de busqueda optimizados:
    • estudiantes: Datos del alumnado activo, grado, curso, jornada y docente titular.
    • docentes: Informacion del cuerpo de profesores y sus asignaciones academicas de grado/curso.
    • grupos: Registra que cursos y grupos estan disponibles por cada grado escolar de manera dinamica.

Analisis Tecnico de Modulos

1. El Corazon de la Automatizacion: Playwright (Python)

El archivo main.py y los modulos de soporte en modules/ utilizan la API sincrona de Playwright para orquestar la navegacion. A diferencia de Selenium, Playwright interactua directamente con los protocolos del navegador Chromium, lo que otorga una mayor velocidad, estabilidad y gestion robusta de descargas.

Bypass de Captcha Matematico (En modules/autenticacion.py)

El login requiere ingresar el resultado de una operacion matematica mostrada en una etiqueta o celda HTML. El sistema utiliza el siguiente flujo:

  1. Analiza el arbol DOM buscando patrones de texto con selectores XPath especificos de operaciones.
  2. Si falla en la localizacion directa, lee el texto del body general y aplica una expresion regular:
    re.search(r'\d+\s*[\+\-\*\/]\s*\d+', body_text)
  3. La cadena capturada es procesada por la funcion _resolver_captcha_matematico, la cual separa los operandos y el operador matematico:
    match = re.search(r'(\d+)\s*([\+\-\*\/])\s*(\d+)', texto)
a, op, b = int(match.group(1)), match.group(2), int(match.group(3))
  4. Retorna el resultado evaluado, el cual es insertado en el campo captcha_respuesta.

Flujo de Scraping de Docentes (Doble Fase)

La extraccion de docentes requiere obtener tanto la lista general como la asignacion de titulares de grado. Esto se realiza en dos fases diferenciadas:

  • Fase A (Titulares por Grado): El bot navega a la seccion de listados, selecciona estudiantes y avanza al segundo paso. Ahi encuentra una tabla con todos los grados de la institucion, cada uno con un link para imprimir el reporte individual. El bot realiza la descarga de cada PDF de forma secuencial guardandolos en downloads/. Luego, usando pdfplumber, lee el encabezado de cada archivo buscando el texto del docente titular mediante expresiones regulares.
  • Fase B (Lista de Docentes General): El bot vuelve al formulario, selecciona la opcion "Docentes" en el selector de tipo de datos, marca "No incluir retirados", y presiona "Siguiente" e "Imprimir". Esto descarga un reporte general en formato PDF.
  • Cruce y Enriquecimiento: Utilizando pandas y la funcion extraer_docentes(), se normalizan los nombres convirtiendolos a minusculas y eliminando espacios en blanco (re.sub(r'\s+', '', nombre).lower()). Se cruzan los registros generales de la Fase B con las asignaciones de la Fase A para determinar que grado y curso le corresponde como titular a cada docente, guardando la informacion final enriquecida en la base de datos PostgreSQL.

Sincronizacion de Estudiantes

El bot navega a la seccion de Estudiantes, descarga el reporte general y utiliza pdfplumber para extraer la informacion estructural de cada fila usando el siguiente patron regular robusto:

PATRON_PERSONA = re.compile(
    r'^\s*(\d+)\s+(\d{5,15})\s+([A-ZÁÉÍÓÚÑ][A-ZÁÉÍÓÚÑ\s]+?)(?:\s+([A-Z0-9]{2})\s+([A-Z0-9]{2}))?\s*$',
    re.IGNORECASE | re.MULTILINE
)

Este patron extrae de forma limpia el consecutivo de fila, el numero de documento nacional, el nombre completo y los codigos internos de grado y curso (ej: grado "01" y curso "02"). Si no hay documento en la fila, la fila es descartada garantizando la sanidad de la base de datos.

2. Logica de Base de Datos y Triggers (PostgreSQL)

La base de datos se comunica con Python mediante la libreria psycopg2 y aplica principios estrictos de consistencia transaccional y reglas de integridad.

Sincronizacion Automatizada mediante Trigger PL/pgSQL

Para mantener la relacion entre docentes y estudiantes sin necesidad de realizar multiples consultas de cruce en tiempo de ejecucion en el backend, se implementa un trigger directamente en la base de datos PostgreSQL (declarado en modules/database.py):

CREATE OR REPLACE FUNCTION fn_sync_titular_estudiantes()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.grado_titular IS NOT NULL AND NEW.curso_titular IS NOT NULL THEN
        UPDATE estudiantes
        SET titular = NEW.nombre
        WHERE UPPER(TRIM(grado_texto)) = UPPER(TRIM(NEW.grado_titular))
          AND UPPER(TRIM(curso))        = UPPER(TRIM(NEW.curso_titular));
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_sync_titular_estudiantes
AFTER INSERT OR UPDATE OF grado_titular, curso_titular, nombre
ON docentes
FOR EACH ROW
EXECUTE FUNCTION fn_sync_titular_estudiantes();

Cada vez que se registra o modifica la asignacion de un docente (por ejemplo, el profesor Juan Perez es asignado al grado "Primero" curso "B"), la base de datos automaticamente actualiza el campo titular de todos los estudiantes que pertenezcan a ese grado y curso especificos, asegurando la consistencia e integridad referencial de forma inmediata.

Reglas de Nulabilidad y Duplicados en Identificadores

  • documento es obligatorio en base de datos (NOT NULL).
  • codigo_interno es opcional (permite nulos) pero cuenta con un indice unico condicional:
    CREATE UNIQUE INDEX IF NOT EXISTS idx_codigo_interno_est 
ON estudiantes(codigo_interno) WHERE codigo_interno IS NOT NULL;
  • Regla de Duplicacion en Insercion/Upsert: Si en el ingreso de datos (masivo o manual) solo se provee el documento_nacional, el backend automaticamente le asigna este mismo valor al codigo_interno para garantizar la doble indexacion (y viceversa si solo viene el codigo_interno). Esto previene registros huerfanos y simplifica las busquedas de informacion.

Modulos de Importacion de la Interfaz Web (React)

La interfaz cuenta con dos robustos modulos para la carga de informacion sin pasar por el proceso de scraping de Playwright:

1. Modulo de Importacion Masiva (MassImport.jsx)

Este componente administra el analisis, mapeo, validacion y carga de lotes de datos de manera altamente interactiva.

  • Procesamiento y Mapeo en Cliente: Al arrastrar un archivo, la libreria SheetJS (xlsx) lo parsea localmente en fileParser.js. Luego, columnMapper.js realiza una aproximacion inteligente de las columnas del usuario utilizando un diccionario de sinonimos predefinido:
    const SYNONYMS = {
  nombre: ['nombre', 'nombres', 'nombre completo', 'estudiante', 'docente', 'nombre y apellido'],
  documento_nacional: ['documento', 'identificacion', 'cedula', 'tarjeta', 'ti', 'cc', 'documento nacional'],
  codigo_interno: ['codigo', 'codigo interno', 'cod', 'id_interno']
}
  • Validacion Previa: En rowValidator.js, se valida la coherencia sintactica del archivo. Si falta una columna requerida de acuerdo al tipo de persona seleccionado (Estudiante o Docente), la importacion se detiene informando al usuario inmediatamente, evitando llamadas innecesarias al servidor.
  • Previsualizacion de Datos: Muestra una tabla estilizada en formato vinotinto/beige con las primeras 5 filas procesadas para que el usuario corrobore que el mapeo es correcto antes de guardar en base de datos.
  • Transaccionalidad en Fallo (Detencion en primer error): Al presionar "Confirmar y procesar", el servidor FastAPI ejecuta la insercion secuencial. Si alguna fila contiene un dato invalido (por ejemplo, una jornada no reconocida o un grado incorrecto), el proceso completo realiza un rollback y se detiene, informando exactamente en que numero de fila ocurrio el error para evitar la carga parcial de informacion.
  • Consola de Procesos Estilizada: Muestra el log en tiempo real de los registros procesados. Se utilizan iconos vectoriales de React (MdCheckCircle para nuevos admitidos, MdAutorenew para actualizaciones por upsert y MdError para rechazos) para brindar una experiencia de usuario premium.

2. Modulo de Ingreso Manual (ManualImport.jsx)

Permite registrar un unico estudiante o docente a la vez a traves de un formulario web adaptativo.

  • Validacion Dinamica en Tiempo Real: Valida cada campo a medida que el usuario escribe o quita el cursor del input. Los campos con inconsistencias se iluminan con un borde rojo sutil y muestran un mensaje de error explicativo.
  • Validacion de Duplicados Cruzados: Al enviar el formulario, se consulta al backend a traves del endpoint /api/check-duplicate enviando el documento y codigo interno. Si el backend retorna que ya existe un registro con cualquiera de esos identificadores, la aplicacion detiene el flujo e interrumpe la pantalla mostrando un modal personalizado de confirmacion que detalla el nombre del registro existente y pregunta al usuario si desea actualizar sus datos de forma segura (Upsert manual).
  • Añadir Grupos de Forma Secuencial: Junto al selector de cursos, el boton "+ Añadir grupo" permite crear nuevas letras de division (A, B, C, D...) dinamicamente. El backend valida secuencialmente (no se puede agregar 'C' si no existe 'B') y guarda el grupo en la tabla grupos de la base de datos de manera persistente.

Guia de Instalacion y Despliegue

Sigue estos pasos ordenados para levantar el entorno completo de ejecucion y desarrollo:

Paso 1: Configurar el Servidor y Dependencias Python

  1. Instala Python 3.10 o superior en el sistema.
  2. Abre una terminal de comandos en la carpeta raiz del proyecto.
  3. Crea un entorno virtual de Python:
    python -m venv venv
  4. Activa el entorno virtual:
    • En Windows (PowerShell):
      .\venv\Scripts\activate
    • En Linux/macOS:
      source venv/bin/activate
  5. Instala las dependencias necesarias:
    pip install -r requirements.txt
  6. Instala los binarios del navegador de Playwright necesarios para el bot:
    playwright install chromium

Paso 2: Configurar la Base de Datos PostgreSQL

  1. Crea una base de datos local en PostgreSQL llamada paz_y_salvo.
  2. Ejecuta el archivo SQL estructural base:
    psql -U tu_usuario -d paz_y_salvo -f sql/setup.sql
  3. Ejecuta el archivo de migracion e inicializacion para actualizar las columnas y la tabla de grupos dinamicos:
    psql -U tu_usuario -d paz_y_salvo -f sql/migrate_import_modules.sql

Paso 3: Definir Variables de Entorno y Credenciales

Abre el archivo config/settings.py e introduce las credenciales de acceso administrativo provistas para el portal WebColegios y las configuraciones de conexion a la base de datos PostgreSQL:

# Credenciales del Portal WebColegios
WEB_USUARIO  = "tu_documento_administrativo"
WEB_PASSWORD = "tu_clave_de_acceso"

# Servidor PostgreSQL
DB_HOST     = "localhost"
DB_NAME     = "paz_y_salvo"
DB_USER     = "postgres"
DB_PASSWORD = "tu_password_de_postgresql"

Paso 4: Preparar y Compilar el Frontend React

  1. Asegurate de tener instalado Node.js (versiones 18 o 20 LTS) en tu sistema.
  2. Abre una consola de comandos en la carpeta de la interfaz web:
    cd frontend
  3. Instala los modulos necesarios:
    npm install
  4. Compila la build de produccion del cliente React:
    npm run build
    La compilacion colocara automaticamente todos los bundles estaticos optimizados dentro de la carpeta static_react/ en el directorio raiz del proyecto, de donde FastAPI los leera directamente.

Guia de Uso y Ejecucion

Ejecucion en Produccion (Servidor Unificado)

Para iniciar la aplicacion de manera integrada en produccion, simplemente corre el siguiente archivo en tu consola:

start_dashboard.bat

O de manera manual ejecutando:

python app.py

Abre tu navegador de preferencia e ingresa a la direccion local http://localhost:8000. Podras visualizar los datos sincronizados, presionar "Iniciar Extraccion" para correr el bot de Playwright en segundo plano o utilizar las pantallas de carga masiva/registro manual de informacion.

Ejecucion en Desarrollo (Servidor de Cambios en Caliente)

Si deseas realizar modificaciones visuales o logicas en el frontend de React y requieres recarga rapida (Hot Module Replacement):

  1. Inicia el backend de FastAPI abriendo una consola en la raiz y ejecutando python app.py (corriendo en http://localhost:8000).
  2. Abre otra pestaña de tu consola en la carpeta frontend/ y corre el servidor de Vite:
    npm run dev
  3. La interfaz correra en http://localhost:5173. Vite tiene configurado un proxy inverso que detecta todas las llamadas con prefijo /api y las redirige hacia el servidor de FastAPI en el puerto 8000, facilitando la depuracion de la base de datos y flujos interactivos de forma inmediata.
